NERV TERMINAL MONITOR - CROSS-PLATFORM SYSTEM

Data Sources

Real Kernel Data: All panel headers show their source path. Real data comes from: /proc/stat (CPU), /proc/meminfo (memory), /proc/net/dev (network), /proc/diskstats (disk), /proc/net/wireless (WiFi), /sys/class/thermal (temperature), /var/log/syslog (logs), /proc/uptime (uptime).

Simulated Visuals: "Connection Matrix" shows random hex activity for visual effect. "Auth Log" displays client-side events only. Source labels indicate "simulated visual" or "client-side events" for these.

Linux Kernel (/proc): Real-time CPU statistics (/proc/stat), memory usage (/proc/meminfo), network counters (/proc/net/dev), disk I/O (/proc/diskstats), wireless info (/proc/net/wireless), and system uptime (/proc/uptime).

Linux Thermal (/sys): Temperature readings from /sys/class/thermal and /sys/class/hwmon for all thermal zones and hardware monitors.

System Logs: Direct read of /var/log/syslog (or /var/log/messages fallback, or journalctl on systemd systems). Log entries are color-coded by severity in the terminal widget.

WiFi Scanning: Uses /proc/net/wireless for interface status, iw command for connected network info, and iwlist scan for available networks.

Windows: WMI interface via wmic command for CPU core count, memory totals. Falls back to Node.js os module.

macOS/Other: Node.js os module for basic memory and load average data.

Visual Encoding

  • Hexagonal CPU Grid: Each hexagon represents one CPU core. Fill level = (user+system)/total jiffies. Color shifts from phosphor-green (idle) to phosphor-orange (load) to red (throttling).
  • 7-Segment Displays: Constructed from Unicode block characters (█▀▄▌▐) to simulate vacuum fluorescent displays. All numeric readouts use this style.
  • Seismic Waveforms: Canvas-rendered jagged line patterns representing real bytes-per-second deltas. Amplitude scales with throughput.
  • Hex Ring Chronograph: 60-position hexagonal ring with rotating solid hex (◉) marking seconds for HQ Time.
  • Terminal Widget: Live syslog output with color-coded severity (green=normal, orange=warning, red=error). Updates every 5 seconds from /var/log/syslog.

Color System (Phosphor CRT)

  • Phosphor-Green (#00ff41): Normal operations, safe states, active sync
  • Phosphor-Orange (#ff6b00): Warnings, moderate load, attention required
  • Red (#ff0040): Critical thermal, memory pressure >90%, system alerts
  • Sage (#8fb3a5): Minimal text labels, metric annotations
  • Burgundy (#0f0505): Cathode-void background

MAGI Column Layout

  • MELCHIOR-1 (硬件): Hardware/Soul - CPU hexagons (/proc/stat), thermal zones (/sys/class/thermal), LCL memory pressure (/proc/meminfo)
  • BALTHASAR-2 (網路): Network/Soul - Seismic waveforms for network I/O (/proc/net/dev), interface carrier status, disk activity (/proc/diskstats), WiFi scanner (/proc/net/wireless, iw). Network statistics show both SESSION (since page load) and LIFETIME (since boot) totals.
  • CASPAR-3 (安全): Security/Soul - WiFi networks, live syslog terminal (/var/log/syslog), connection matrix (simulated visual), auth log (client-side events), system status hexes, uptime display (/proc/uptime)

Technical Implementation

Update interval: 500ms for system metrics, 5 seconds for syslog, 10 seconds for WiFi scanning. Smooth waveform rendering while maintaining low CPU overhead.

History buffer: 60 samples (30 seconds) for seismic waveform amplitude calculation.

API endpoints: /api/system (current state), /api/system/history (waveform data), /api/system/syslog (log entries), /api/system/wifi (networks).

Source labels in panel headers indicate real (/proc/..., /sys/...) vs simulated ("simulated visual", "client-side") data.

Cross-Platform Compatibility

This interface adapts automatically to the host platform:

  • Linux: Full functionality with /proc, /sys access, and live syslog tailing
  • Windows: CPU count, memory via WMI; limited thermal/network/syslog data
  • macOS: Basic memory and load via Node.js os module; syslog via journalctl if available
