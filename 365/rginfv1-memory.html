RGInfV1 research note

Memory system

RGInfV1 made memory explicit, inspectable, and local. A JSON fact store sat beside saved conversation history. Configurable trigger phrases and model-assisted extraction produced candidate facts; enabled state, keyword overlap, duplicate suppression, and a top-three limit determined what entered the next system prompt.

The implemented system

A small memory architecture with visible boundaries.

The module used ordinary files and explicit routes instead of pretending the model retained state internally. Facts persisted in memory.json; conversation threads persisted separately. Every fact carried an ID, content, keywords, confidence, source, enabled flag, and creation time. The distinction mattered: transcript persistence could restore an episode, while fact memory could cross episodes without replaying every turn.

01 / CAPTURE

Two extraction paths

Configurable phrases such as “I prefer,” “I use,” and “remember that” marked likely memory-bearing messages. A second path asked the currently loaded Ollama model to extract facts deliberately. Both produced explicit records rather than hidden conversational state.

02 / SCHEMA

Facts carried operational metadata

The stored object included content, keywords, confidence, source, enabled state, creation time, and a generated ID. That schema supported review and control even when not every field yet participated in ranking.

03 / DEDUPE

Containment blocked obvious repeats

Before insertion, normalized content was checked for exact equality and, for longer facts, substring containment in either direction. It was intentionally lightweight: useful against repeated extraction, but not a semantic contradiction detector.

04 / CONTROL

Memory could be disabled or removed

Fact routes supported add, delete, toggle, clear, and full inspection. Keyword routes supported add, remove, and replacement. The user could see and alter the mechanism instead of relying on an inaccessible model-side profile.

Retrieval and injection

Relevance was simple enough to inspect.

Only enabled facts were candidates. The current message was compared against stored keywords, overlap produced a relevance score, and the three strongest matches were appended to the system context. This was not an embedding database or latent autobiographical memory. It was a bounded lexical retrieval system whose behavior could be traced from input phrase to injected fact.

FILTER

Enabled state formed the first boundary

A stored fact could remain in the archive without participating in inference. That separated deletion from temporary suppression and made context assembly reversible.

SCORE

Keyword overlap ranked candidates

The score was interpretable: matched terms raised a fact; absent terms did not. The method lacked paraphrase recall, but it also avoided opaque similarity behavior and made relevance failures easy to diagnose.

LIMIT

Top three protected the context budget

Selection stopped after three facts. The hard limit prevented the memory store from expanding the system prompt without bound and forced the system to choose rather than dump.

INSPECT

Full context stayed visible

The interface could show the combined system prompt and injected memory facts. That made the actual model input auditable—a stronger guarantee than merely displaying what existed in storage.

What the implementation exposed

The next problems were ranking, conflict, and consolidation.

Once the pipeline existed, its research questions became concrete. Confidence and source were stored but lexical overlap dominated retrieval. Substring deduplication could catch repetition but not contradiction. A flat fact list could preserve preferences yet could not represent temporal validity, project scope, supersession, or relationships among records.

RECALL

Paraphrases can miss

A message may express the right concept without repeating a stored keyword. Dense retrieval or learned reranking could improve recall, but would need evaluation against false semantic neighbors.

CONFLICT

New facts can oppose old ones

A mature memory layer needs temporal ordering and supersession rather than keeping two enabled claims as if both remain true. Provenance makes that resolution reviewable.

SCOPE

Relevance is contextual

A preference can be global, project-specific, person-specific, or temporary. Scope should constrain retrieval before ranking so a strong lexical match from the wrong domain does not win.

CALIBRATE

Confidence needs semantics

A numeric confidence field only becomes meaningful when its source, scale, and update rule are defined. Extraction certainty, truth confidence, and retrieval relevance are different quantities.

Continuity comes from selection, not accumulation.

RGInfV1’s system was valuable because its mechanism remained visible: a fact could be traced from capture, through storage and overlap ranking, into the exact system context the local model received. The limitations were not hidden; they became the next research agenda.
