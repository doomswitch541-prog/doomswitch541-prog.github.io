RGInfV1 research note

Memory system

A saved transcript is history. Memory is the process that decides what returns. RGInfV1’s memory work separated the current conversation from durable records, then asked how the right pieces could be selected and placed back into context when they mattered.

What the system has to do

Remember selectively, not endlessly.

Language models do not carry a private recollection from one request to the next. Each request receives a constructed context. A memory system makes that construction deliberate: it stores candidate records, decides what is relevant now, and gives the model a compact packet with enough origin information to understand why it is there.

01 / CAPTURE

Turn experience into records

Messages, decisions, preferences, project facts, and summaries need different shapes. A useful record includes the information itself, when it was learned, where it came from, and what scope it belongs to.

02 / SELECT

Retrieve for the present task

Recall can combine semantic similarity with recency, importance, project identity, tags, and explicit pins. Similar wording alone is not enough; a nearby memory can still be wrong for the current situation.

03 / PACK

Fit memory into context

Retrieved records compete with conversation history, system instructions, source material, and room for the answer. Deduplication, ranking, summaries, and token budgets keep the packet useful instead of merely large.

04 / REVISE

Let memory change cleanly

New evidence can supersede an older record. Corrections should preserve provenance, avoid silent rewriting, and distinguish a stable preference from a temporary statement made inside one conversation.

The memory loop

Write, retrieve, compose, answer, update.

WORKING

The prompt in front of the model

The active window holds the immediate exchange. It is fast and precise, but finite. Once material falls outside that window, it only returns if another system carries it forward.

EPISODIC

What happened in a specific exchange

Conversation turns and summaries preserve sequence: what was tried, what failed, what was decided, and what remains unfinished. Time and project boundaries matter as much as semantic similarity.

SEMANTIC

Knowledge abstracted from episodes

Stable facts and learned preferences can be stored separately from the transcript that produced them. That makes them easier to retrieve, while provenance keeps the abstraction accountable to its source.

CONTROL

Memory should remain inspectable

A local system can show what it kept, what it recalled, and why. Explicit edits, deletions, pins, and scope controls prevent an invisible memory layer from quietly defining the conversation.

Continuity comes from selection, not accumulation.

The useful memory is not the largest archive. It is the smallest set of trustworthy records that restores the right context, preserves the thread, and leaves enough room for the model to think about what is happening now.
