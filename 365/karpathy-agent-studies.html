Beginner

Make the abstractions small enough to see.

The useful starting point was not “build an autonomous agent.” It was learning what the model actually does. Text becomes token IDs. Parameters turn those tokens into vectors. Attention moves information between positions. A forward pass produces logits, a loss measures error, backpropagation assigns gradients, and an optimizer makes a small update. Sampling turns the resulting probability distribution back into a sequence.

Autograd makes learning mechanical. Each operation records local derivatives; reverse-mode differentiation composes them backward from one scalar loss.

Prediction happens one token at a time. Even a conversational answer is an autoregressive loop: read the current sequence, score possible next tokens, choose one, append it, repeat.

Small code changes the kind of understanding available. When the whole system fits in one file, every variable can be traced and every hidden convenience becomes an explicit decision.

Intermediate

MicroGPT as an inspectable stack.

Karpathy describes MicroGPT as an atomic, dependency-free Python implementation of the GPT algorithm. Its value is not that a tiny model replaces a production system; it is that the training and generation pipeline becomes legible as one connected mechanism. Dataset preparation, tokenization, scalar-valued automatic differentiation, transformer attention, the MLP, optimization, and sampling stop looking like unrelated libraries.

p(x) = ∏ p(xₜ | x₍₁…ₜ₋₁₎)

The model is state transformation. Embeddings and residual updates carry a representation forward while attention and the MLP contribute different computations at every layer.

Training and inference are related loops. Training adds targets, loss, gradients, and parameter updates; inference holds weights fixed and repeatedly extends the sequence.

Readable implementations expose tradeoffs. Context length, layer width, head count, initialization, learning rate, temperature, and sampling policy are no longer mysterious settings outside the program.

Agent engineering

Add software around the model deliberately.

An agent can be understood as a model embedded in a controlled state machine. The model proposes an action; software validates it; a tool produces an observation; the observation enters the next step; a stop rule ends the loop. Reliability comes less from naming the loop “agentic” than from engineering each boundary so failures are visible and recoverable.

state → model → validated action → tool → observation → state

Tools are typed interfaces. Arguments need schemas, paths need scope, results need size limits, and errors need to return as data the next step can reason about.

The loop needs bounds. Step limits, timeouts, cancellation, permissions, and explicit completion conditions prevent “keep going” from becoming the entire control system.

Observability is part of the interface. Showing the current step, tool request, result, and terminal state makes a local agent understandable instead of magical.

The path into RGClaw

Software engineering first; identity second.

RGClaw grew from this line of study: understand the smallest model loop, then add tools, state, execution policy, and a visible runtime one layer at a time. It was not an attempt to copy OpenClaw. The project came from reconstructing agent behavior from first principles and asking what a useful local runner actually needs.

STATE

Keep the working record explicit

Inputs, model output, tool calls, observations, and completion state belong to a trace the runtime can inspect rather than an invisible chain of side effects.

TOOLS

Separate proposal from execution

The model can request an operation, but ordinary software decides whether the request is valid, authorized, correctly shaped, and safe to run.

POLICY

Bound what a run may become

Workspace scope, allowed capabilities, step budgets, time limits, and cancellation turn open-ended generation into a controlled task process.

TRACE

Make progress observable

A useful interface distinguishes waiting, inference, tool execution, recovery, completion, and failure so the human can understand the system without guessing.

Later extension · AutoResearch

Let the loop modify an experiment, not its rules.

AutoResearch provided a later, sharper example of bounded agency. The preparation and evaluation surface stays fixed while the agent edits the training program, runs a five-minute experiment, reads a single validation metric, and decides whether to keep or discard the result. The autonomy is real, but it lives inside an unusually clear experimental contract.

FIXED

Protect the harness

Data preparation and evaluation define the comparable environment. Leaving them unchanged prevents the agent from improving the score by changing the test.

MUTABLE

Constrain the research surface

The agent modifies one training file. That is enough freedom to try architectural and optimization ideas without turning every repository file into an uncontrolled variable.

BUDGET

Normalize experiments by time

A fixed runtime makes iteration speed part of the design and keeps results comparable on the same hardware.

METRIC

Close the empirical loop

Validation bits per byte supplies a concrete signal. The result is recorded, compared, and either retained or reverted before the next hypothesis.

Primary references: Karpathy’s GitHub profile and the AutoResearch repository.

The agent was never one mysterious thing. It was a set of small loops with boundaries.

That progression—from learning the model’s mechanics to engineering the runtime around it—is the study line that made RGClaw possible.
