Local coding harness

RGCode

Run local coding models on real projects — and watch the whole loop.

A code-first workspace for tool-capable local models. It hands the model a project and real file and shell tools, runs the loop on Ollama by default or through RGModelServe, and keeps every step in view: the context it got, the tools it called, what came back, and why it stopped.

01 · What it is

It gives a local model a project and real tools.

Point it at a workspace project and pick a model. RGCode runs the loop — read context, call a tool, get a result, go again — with no routing tricks or model swaps in the way. Sixteen tools, grouped by what they touch.

02 · The run loop

One loop, up to twenty turns.

Each turn assembles the context, streams the model, runs one tool call, and feeds the result back. It repeats until the model gives a final answer or the run hits a stop — and the stop reason is always recorded.

context→ stream→ tool call→ execute→ result↺

↺ feed the result back and go again — same session context, until a stop.

03 · What it keeps

Durable Markdown, not hidden memory.

Project knowledge lives in plain Markdown you can open and edit — rooted to the project, not buried in a chat log. Every run is written to disk so the history stays trustworthy.

RGCODE.md

The project's durable memory — what it is, decisions, notes.

TASKS.md

The working task list the model reads and updates.

RUNS.md

A human-readable log of runs and what each one did.

SETUP.md

Environment commands deferred for you to run by hand.

Full traces persist under .rgcode/runs/ — one file per run, every step replayable.

04 · Tool readiness

Advertised isn't the same as usable.

A model can claim tool support from Ollama and still ship a chat template that never actually shows it the tools. RGCode audits the template first — advertised capability plus whether the tools, tool calls, and results survive the loop — and grades each model before trusting it. Fable 5 is the model this is built to learn from.
