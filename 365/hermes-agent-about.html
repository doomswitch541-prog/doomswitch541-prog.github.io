The route

Keep the client simple. Let the gateway know the machine.

The Hermes client only needed a compatible endpoint and a model name. RGModelServe carried the local complexity: discover what was running, expose stable aliases, route requests to Ollama or llama.cpp, preserve the tool-call format, and return one consistent response shape to the tablet.

CLIENT

The tablet asks in a standard language

Hermes Agent uses an OpenAI-compatible request shape. That keeps the mobile client independent from the details of the model runtime behind it.

GATEWAY

RGModelServe owns the translation

The gateway presents one local surface while routing each model alias toward the backend capable of serving it. The interface stays stable even when the underlying runtime changes.

MODEL

Coder models run on local hardware

The operational path favors local llama.cpp coder backends sized for the machine. Larger and smaller variants make model choice an allocation of capability, latency, and available memory.

TOOLS

Structured calls survive the route

Templates and parsers preserve the difference between ordinary text and a requested tool action. That turns the tablet from a remote chat box into a client for a local agent loop.

The messenger traveled. The data stayed on the local road.

Hermes mattered because it separated the place where a request began from the machine that could answer it. A tablet could carry the interface while the gateway, model weights, memory pressure, and tool execution remained under local control.
