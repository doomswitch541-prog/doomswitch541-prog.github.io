The first concepts

Make the machinery visible enough to understand.

MODEL / CHOOSE

Selection is part of the conversation

Different local models carry different sizes, speeds, and voices. The interface needed to make that choice explicit instead of treating the model as an invisible default.

RESPONSE / STREAM

Arrival matters

A live token stream turns waiting into feedback. It shows that generation has begun, gives the response a rhythm, and makes local inference feel responsive before the final sentence exists.

THREAD / RETURN

A conversation should have a place

Messages needed a stable thread that could be reopened and continued. Persistence was not an extra feature; it was what separated a lasting interface from a one-shot prompt box.

STATE / SEE

Local should be legible

Connection state, the selected model, generation progress, and failures belong where the person can see them. The interface should reveal the path without burying the conversation in diagnostics.

The model was local. The interface had to make it feel present.

This beginning established the shape of RGInfV1: a browser-based room, a small local bridge, a chosen Ollama model, and a response returning as a stream. The work from here was to turn those pieces into one coherent conversation.
